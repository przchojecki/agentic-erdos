# EP-734

## Problem Statement
Find, for all large $n$, a non-trivial pairwise balanced block design $A_1,\ldots,A_m\subseteq \{1,\ldots,n\}$ such that, for all $t$, there are $O(n^{1/2})$ many $i$ such that $\lvert A_i\rvert=t$.

## Site Remarks
$A_1,\ldots,A_m$ is a pairwise balanced block design if every pair in $\{1,\ldots,n\}$ is contained in exactly one of the $A_i$.

Erd\H{o}s \cite{Er81} writes 'this will be probably not be very difficult to prove but so far I was not successful'.

Erd\H{o}s and de Bruijn \cite{dBEr48} proved that if $A_1,\ldots,A_m\subseteq \{1,\ldots,n\}$ is a pairwise balanced block design then $m\geq n$, and this implies there must be some $t$ such that there are $\gg n^{1/2}$ many $t$ with $\lvert A_i\rvert=t$.

## Local Computation
- Built a finite heuristic proxy by edge-partitioning \(K_n\) into cliques (interpreted as blocks), with randomized greedy growth from uncovered edges.
- Measured the maximum multiplicity among block sizes in best runs across multiple restarts.

- Deep run for \(n=25\) to \(121\) (36 trials each) gave best-found max multiplicities much larger than \(\sqrt n\) (ratios about 7-33).
- The obstruction in this heuristic is strong accumulation of small blocks (especially size 2), indicating this naive decomposition is far from the target regime.

## Local Proof Attempts
I used a finite clique-partition proxy for pairwise balanced designs, treating clique sizes as block sizes and measuring how concentrated the resulting size multiplicities become. The outcome is mostly negative for this heuristic: small blocks accumulate too heavily, so the construction is nowhere near the desired uniform \(O(\sqrt n)\) multiplicity profile. The note remains open and the current heuristic is inadequate.
